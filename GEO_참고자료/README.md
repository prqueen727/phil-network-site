## 무엇을 만드나

**GEO(생성형 검색 최적화) 특화 홈페이지** = 프론트(방문자·봇이 읽음) + 관리자 페이지 + 네이버 자동발행.

**확정 스택:** Supabase(Postgres + Auth + RLS) + Next.js(Vercel) + Cloudflare R2(미디어) + Railway(자동발행 스케줄러)

```
STEP 0    사이트 유형 질문
STEP 0.5  요구사항 문답 + 디자인 해체          ★규칙 0 (실측 강제)
STEP 1~2  Supabase 스키마 + 관리자 계정
STEP 3    프론트 구현 (SSR JSON-LD)            ★검사 3번 + 밀도 규칙
STEP 4    R2 미디어                            ★글쓰기보다 먼저
STEP 5    관리자 UI
STEP 6    네이버 리라이팅
STEP 7    자동발행 스케줄러
STEP 8    배포
STEP 9    검색엔진·AI봇 노출 개통              ★여기까지 해야 끝
```

## 절대 규칙 (전 STEP 공통)

1. **임의 생성 금지** — 벤치마킹 값은 전부 원본 소스에서 실측. 요약(WebFetch)은 재현 재료가 아니다.
2. **콘텐츠는 DB에** — `data/*.ts` 하드코딩 금지. 운영자가 코드 없이 고칠 수 있어야 한다.
3. **`saveBlogWithJsonLd()` 경유** — blogs에 직접 insert 금지 (JSON-LD 누락 방지).
4. **SSR 필수** — JSON-LD·메타는 서버가 보내는 첫 HTML에 있어야 한다. `curl`로 확인.
5. **상호명 유출 0건** — 벤치마킹 원본의 상호·실명·전화·도메인이 산출물에 남으면 법적 사고.
6. **검증 없이 다음 STEP 금지** — "된 것 같다"로 넘어가지 말고 실제로 실행해 관찰한다.
7. **없는 서비스를 스키마에 넣지 마라** — 실제 사고(AI가 소개 → 클레임 → 롤백) 사례가 있다.
