# 벤치마킹 실전 해부 가이드 — DOM·CSS·JS·인터랙션 실측법

# 🚫 규칙 0 — 임의 생성 절대 금지 (이 문서의 존재 이유)

> **너(AI)에게: 벤치마킹 작업에서 값·섹션·구조·속도·색·폰트·간격을 "생각해서" 넣는 것을 전면 금지한다.**
> 모든 것은 **원본 소스(HTML/CSS/JS)에서 실측한 값만** 쓴다. 이 문서를 받고도 임의값을 넣으면 문서를 만든 이유가 없어진다. **목표는 벤치마킹 사이트와 99% 동일한 재현이고, 그건 한 번에 나와야 한다.**
>
> **금지 항목 (하나라도 어기면 실패):**
> - ❌ 애니메이션 속도를 "적당히" 넣기 (예: 임의 30s) → ✅ CSS `animation-duration` 실측값 그대로
> - ❌ 섹션을 "이 정도면 되겠지"로 구성/누락 → ✅ DOM `<section>` 전수, 순서·개수 그대로
> - ❌ 색·폰트·크기·간격을 눈대중/추측 → ✅ CSS에서 hex·px·%·s 실측
> - ❌ 인터랙션을 겉보기로 추측(슬라이더냐 스냅이냐) → ✅ 커스텀 JS 정독으로 정체 확정
> - ❌ 슬라이드 개수·내용을 짐작 → ✅ 요소/제목/이미지 세트 수로 교차 확인
> - ❌ "요약(WebFetch)"을 재현 재료로 사용 → ✅ 방향 감각용으로만, 재료는 raw 소스
>
> **확인 못 한 값은 지어내지 말고 `[미확인]`으로 표시하고 사용자에게 원본 소스(DevTools 덤프)를 요청하라.** 추측을 사실인 척 넣는 것이 최악이다.
>
> **작업 순서 강제:** 아래 STEP A→B→C→D→E를 **전부 실행한 뒤에** 코드를 짜기 시작한다. 소스를 다 받기 전에 "일단 만들고 나중에 맞춘다"를 금지한다 — 그게 임의 생성이다.
>
> **실증(왜 이 규칙이 생겼나):** 이 규칙 없이 작업하다 같은 실수를 5번+ 반복했다 — 색 오인, 섹션 4개 누락, 슬라이더를 카드로, 4슬라이드를 1개로, 마퀴 속도를 4배 빠르게(임의 30s vs 실측 120s). 매번 사용자가 스크린샷으로 반박해야 했다. **전부 "실측 안 하고 생각해서 넣어서"** 생긴 것이다.

## ★ 철칙 — 요약은 벤치마킹이 아니다

**WebFetch가 반환하는 것은 "요약"이지 원본이 아니다.** 요약 기반 재현은 반드시 아래처럼 틀린다:

| 요약이 알려준 것 (틀림) | 실제 소스 (맞음) | 실패 결과 |
|---|---|---|
| "black/white 미니멀" | `#101010` + 골드 `#f5cd4f`/`#fdd000` (CSS 실측) | 색을 흑백으로 만듦 |
| "시스템 산세리프 추정" | Pretendard (CSS `@font-face` 실측) | 우연히 맞았을 뿐 |
| "3열 그리드 카드" | 무한 연속 슬라이더 + 마퀴 (DOM `n_*_slider` 실측) | 정적 그리드로 만듦 |
| "7~8개 섹션" | 10개 섹션 (DOM `<section>` 전수) | 4개 섹션 누락 |
| "메인 슬라이더 = 배너" | CLINICAL EXPERTISE 4슬라이드 순환 (DOM `n_feature_item` 실측) | 진료일정 배너로 오인 |

**결론: 벤치마킹은 반드시 실제 HTML/CSS/JS를 받아서 한다. 요약은 방향 감각용일 뿐, 재현 재료로 쓰지 마라.**

## 정확도 순위 (해체 프롬프트 §169와 동일 원칙, 구체화)

```
사용자 DevTools 덤프(Copy outerHTML)  >  curl로 raw HTML+CSS+JS 직접 fetch  >  WebFetch 요약  >  스크린샷만
        (렌더된 DOM 그대로)              (이 문서의 핵심 방법)          (방향만)      ([추정] 폭증)
```

- **SPA(React/Vue)면** 초기 HTML이 비어 있을 수 있다 → 사용자에게 DevTools 덤프 요청.
- **WordPress·아임웹·Cafe24 같은 서버렌더 사이트면** curl raw HTML에 콘텐츠가 다 들어있다 → 이 문서 방법으로 충분.
- 판별: `curl`한 HTML에 실제 텍스트·클래스가 보이면 서버렌더(그대로 분석), `<div id="root"></div>`만 있고 비었으면 SPA(덤프 요청).

## ✅ 실제로 성공한 표준 플로우 (잭피부과 재구현 실증 — 이대로 하면 한 번에 나온다)

> 아래는 **처음엔 임의로 하다 5번 실패한 뒤, 이 순서로 바꾸니 한 번에 성공한** 실제 플로우다. 재사용 스크립트는 [벤치마킹-실측-스크립트/](벤치마킹-실측-스크립트/) 폴더에 있다.

```
1) 원본 3종 받기     : curl로 home.html + all.css(조각 전부 합침) + custom.js(테마 JS)
2) py 스크립트로 실측 : py 1-spec-extract(색·폰트·애니속도·섹션순서)
                       py 2-interaction-extract(리빌 클래스·keyframes·stagger·트리거)
                       py 3-section-extract(섹션별 내부구조)  → [1] 섹션순서로 SECTIONS 교체
                       py 4-detail-css(좌우비율·오버레이 정밀 CSS)
3) SPEC SHEET 채우기  : 위 출력을 design/SPEC_SHEET.md 표에 100% 옮김 (빈칸=코딩금지)
4) 구현              : 표를 "구현"만. 색만 자사 톤 치환, 상호는 자사명. 새 값 발상 금지
5) 검증              : Playwright로 리빌 실측값 확인 + 원본↔재현 스크린샷 대조 + 모바일 0
```

### ⚠️ 이번에 실제로 발목 잡은 함정 3가지 (반드시 피하라)

1. **`python3`가 Store 스텁이라 "파이썬 안 된다"고 오판** → 실제론 `py`/`python`이 진짜 파이썬. `py --version`으로 먼저 확인. (이걸 몰라 섹션 파싱을 대충 grep으로 때우다 구조를 놓쳤다.) **단, 색·애니속도 같은 단순 실측은 파이썬 없이 bash grep만으로도 된다 — 파이썬은 섹션 파싱 편의일 뿐, 도구 없다고 실측 자체를 건너뛰지 마라.**
2. **"요약 봤으니 실측했다"는 착각** → 요약 몇 줄 = 실측 아님. 소스를 열어 값을 뽑은 게 실측이다.
3. **리빌 `translateX(±100px)` 초기값이 모바일 가로 오버플로를 만듦** → `html, body, main { overflow-x: hidden }`으로 차단(원본도 그렇게 함).

### 왜 임의로 하게 되는가 (자기점검)

능력 부족이 아니라 **순서를 안 밟는 습관**이다: ①"일단 그럴듯하게 만들고 반응 보자"는 성급함 ②실측을 검증 뒤로 미룸 ③요약을 실측으로 착각. → **규칙 0 + SPEC SHEET(코딩 전 실측 완료)가 이 습관을 막는 강제 장치다.**

## STEP A — raw HTML 받기 + 기술스택 판별

```bash
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120.0 Safari/537.36"
curl -s -A "$UA" https://{target}/ -o home.html -w "HTTP %{http_code} · %{size_download}b\n"

# 기술스택 판별 (재현 방식이 갈린다)
grep -ioE 'wp-content|wordpress|imweb|아임웹|cafe24|godomall|/_next/|__NUXT__|data-reactroot|wix' home.html | sort -u
```

- `wp-content` → **WordPress + 커스텀테마** (테마 JS/CSS가 인터랙션의 핵심)
- `/_next/` → Next.js, `__NUXT__` → Nuxt, `data-reactroot` → React SPA
- **왜 중요:** WordPress면 테마의 `n_script.js` 같은 커스텀 JS에 슬라이더·리빌 로직이 다 있다. 그걸 받아 읽으면 인터랙션의 정체가 나온다.

## STEP B — 실제 CSS 전부 받아서 디자인 토큰 실측

WordPress·최적화 플러그인은 CSS를 **여러 파일로 쪼갠다**(FVM 등). 전부 받아 합쳐야 진짜 색·폰트가 나온다.

```bash
# HTML에서 모든 CSS URL 추출 → 전부 받아 합치기
grep -oE 'href="[^"]*\.css[^"]*"' home.html | sed 's/href="//;s/"$//' | sort -u > css_urls.txt
rm -f all.css; while read u; do curl -s -A "$UA" "$u" >> all.css; echo >> all.css; done < css_urls.txt

# 실제 색상 (빈도순 = 디자인 토큰 우선순위)
grep -oiE '#[0-9a-f]{6}' all.css | tr 'A-F' 'a-f' | sort | uniq -c | sort -rn | head -20

# 실제 폰트
grep -oE 'font-family:[^;}]*' all.css | sort | uniq -c | sort -rn | head
grep -oE 'https?://[^)"'"'"']*\.(woff2?|ttf)' all.css | sort -u | head
```

- **빈도 상위 hex가 곧 핵심 토큰**이다. 텍스트색·배경·포인트·라인이 여기서 나온다.
- 인라인 `<style>`의 색은 CMS 기본 팔레트(워드프레스 `#f5cd49` 등)일 수 있으니, **테마 CSS 파일의 빈도**를 우선한다.

## STEP C — DOM 섹션 전수 (누락 0)

**메인 페이지 섹션을 하나도 빠뜨리지 않는다.** 이름만 보지 말고 순서대로 전수.

```bash
# 최상위 섹션/주요 블록을 DOM 등장 순서대로
grep -oE '<(section|div)[^>]*class="[^"]*"' home.html | \
  grep -oE '[a-z_]*section|hero[a-z_]*|main_slider|[a-z_]*_slider' | awk '!seen[$0]++'

# 각 섹션의 실제 타이틀 텍스트 (섹션 정체 확인)
grep -oE '_main_title[^>]*>[^<]+|_title[^>]*>[^<]+' home.html | sed 's/.*>//' | grep -v '^$'
```

- **함정:** 고유 클래스 없는 섹션은 `section`/`div`로만 잡혀 놓치기 쉽다. 스크린샷과 대조해 "화면엔 있는데 grep에 없는" 섹션을 찾아라. (실증: CLINICAL EXPERTISE 섹션이 `main_slider` **안에** 들어있어 별도 섹션으로 안 보였다.)
- **콘텐츠가 이미지 안 텍스트면** grep에 안 잡힌다. `alt=""`나 이미지 파일명(`home_img2_001.png`)으로 유추하고, 안 되면 스크린샷으로 확인.

## STEP D — ★인터랙션의 정체를 소스에서 확인 (이 문서의 핵심)

"스크롤하면 움직인다"를 눈으로만 보고 추측하지 마라. **어떤 방식인지 JS 소스로 확정**한다.

### D-1. 어떤 라이브러리/방식인가

```bash
# 스크롤/슬라이더 라이브러리 힌트
grep -ioE 'fullpage|pagePiling|swiper|slick|scrollmagic|gsap|scrolltrigger|locomotive|aos|wow\.js|wheel|mousewheel' home.html | sort | uniq -c

# 로드되는 JS 목록 (테마 커스텀 JS가 핵심)
grep -oE 'src="[^"]*\.js[^"]*"' home.html | sed 's/src="//;s/"$//' | grep -iE 'theme|main|custom|script|slider'
```

### D-2. 커스텀 JS를 받아서 실제 로직 정독

```bash
curl -s -A "$UA" "https://{target}/wp-content/themes/{theme}/js/{custom}.js" -o custom.js
grep -inE 'wheel|scrollTo|preventDefault|deltaY|IntersectionObserver|new ScrollMagic|\.Scene|triggerHook|setInterval|snap|fullpage' custom.js
```

### D-3. "풀페이지 스크롤"의 진짜 정체 판별 (실증 사례)

사용자가 "풀페이지 스크롤"이라 불러도 **3가지가 다 다르다.** 소스로 구분하라:

| 겉보기 | 실제 방식 | 소스 증거 | 재현법 |
|---|---|---|---|
| 한 스크롤=한 섹션 점프 | fullPage.js 스냅 (wheel 하이재킹) | `wheel` + `preventDefault` + `scrollTo` 섹션단위 | scroll-snap 또는 fullPage 계열 |
| 스크롤 시 요소가 나타남 | **스크롤 리빌** (대부분 이것) | `n_reveal_up` 클래스 + ScrollMagic/IntersectionObserver | IntersectionObserver + CSS transition |
| 가로로 계속 흐름 | 무한 마퀴/오토슬라이더 | `setInterval` 또는 CSS `@keyframes translateX` | CSS animation |

**실증:** vos.co.kr은 겉보기엔 "풀페이지 스크롤"이었지만, `n_script.js`를 정독하니 **ScrollMagic+GSAP 기반 스크롤 리빌**(`n_reveal_up`)이었고, 그 안의 `scrollTo`는 모바일 페이지네이션 버튼용이었다. 진짜 풀페이지 스냅이 아니었다. → 요약/겉보기로 판단했으면 fullPage.js를 잘못 붙였을 것.

### D-4. 슬라이더의 슬라이드 개수·내용 실측

```bash
# 슬라이드 단위 요소 개수 (몇 장이 순환하는지)
grep -oc 'swiper-slide\|slick-slide\|n_slide_item\|n_feature_item' home.html
# 각 슬라이드의 제목/서브/이미지 (내용)
grep -oE 'n_feat_title[^§]{0,250}' home.html | grep -oE '>[^<]+<' | sed 's/[<>]//g'
grep -oE 'n_feat_img[^§]{0,200}' home.html | grep -oE '[a-z_]*\.(png|jpg|webp)'
```

**실증:** vos CLINICAL EXPERTISE는 grep 카운트가 "1"로 보였지만(한 컨테이너에 뭉침), 실제 제목·이미지는 **4세트**(Precision/Clinical/Academic/Proven + `home_img2_001~004.png`)였다. **개수를 grep 카운트만 믿지 말고 제목/이미지 세트 수로 교차 확인**하라.

### D-5. ★애니메이션 속도(duration)도 실측해서 맞춰라

**"움직인다"만 재현하고 속도는 임의로 넣으면 무드가 완전히 달라진다.** 흐르는 속도는 CSS `animation-duration`에 있으니 실측해서 그대로 쓴다.

```bash
# 모든 애니메이션 duration 전수 (마퀴·슬라이더·히어로)
grep -oiE 'animation:[a-z_ ]*[0-9]+m?s|animation-duration:[0-9]+m?s' all.css | sort | uniq -c | sort -rn
# 특정 요소의 애니메이션 (마퀴 트랙 등)
grep -oiE '[a-z_]*marquee[a-z_]*[^{]*\{[^}]*\}' all.css
```

**실증:** vos 뷰 섹션 대형 브랜드 마퀴는 `animation: marqueeLeft 120s linear infinite` + `font-size:130px`였다. 임의로 30s를 넣었더니 **4배 빠르게 흘러** 무드가 전혀 달랐다. 실측해 120s/130px로 맞추니 원본처럼 아주 천천히 흐른다. 폰트 크기·패딩(`padding:60px 0`, 모바일 `40px`/`60px`)도 CSS에서 실측해 반영한다.

**재현물 속도 검증:** Playwright로 `getComputedStyle(track).animationDuration`을 읽어 실측값과 일치하는지 확인한다(정적으로 "애니 있음"은 속도 증명이 아니다).

### D-6. ★대형 타이포·워터마크 텍스트도 섹션 요소다 — 자사명으로 치환

배경에 크게 흐르는 브랜드 텍스트(예: `VOS DERMATOLOGY CLINIC`)는 **디자인 요소이자 원본 상호**다. 두 실수를 동시에 조심:
- **누락 금지:** 이 대형 타이포가 섹션 무드의 절반이다. 카드·이미지만 재현하고 빠뜨리면 원본과 확연히 다르다.
- **치환 필수:** 그 텍스트를 그대로 두면 원본 상호 유출(규칙 11). **벤치마킹해오는 순간 `{상호명}`으로 치환**해 자사명(예: `JACK DERMATOLOGY CLINIC`)으로 재현한다. 이미지 안 텍스트(간판·로고)는 재사용 금지 → 자사 에셋으로 대체.

## ★ STEP D.5 — 코딩 전 필수 산출물: 실측값 대조표 (SPEC SHEET)

**코드를 한 줄이라도 짜기 전에, 아래 표를 원본 소스에서 실측한 값으로 100% 채운다.** 빈칸이 있으면 코딩 시작 금지 — 빈칸을 임의값으로 메우는 것이 곧 이 문서가 막으려는 실수다. 채우지 못한 칸은 `[미확인 — DevTools 덤프 필요]`로 남기고 사용자에게 요청한다.

한 방에 대부분 뽑는 명령 (all.css + home.html 대상):
```bash
# 색 팔레트 (빈도순)
grep -oiE '#[0-9a-f]{6}' all.css | tr 'A-F' 'a-f' | sort | uniq -c | sort -rn | head -20
# 폰트 + weight
grep -oiE 'font-family:[^;}]*|font-weight:[0-9]+' all.css | sort | uniq -c | sort -rn | head
# 모든 애니메이션 이름+속도
grep -oiE 'animation:[a-z_ ]*[0-9]+m?s|animation-duration:[0-9]+m?s' all.css | sort | uniq -c | sort -rn
# 주요 요소 font-size/padding/gap/radius
grep -oiE '(font-size|padding|gap|border-radius|line-height):[^;}]*' all.css | sort | uniq -c | sort -rn | head -30
# 섹션 전수(순서)
grep -oE '<(section|div)[^>]*class="[^"]*"' home.html | grep -oE '[a-z_]*section|[a-z_]*_slider|hero[a-z_]*' | awk '!seen[$0]++'
```

**대조표 양식 (전부 실측값으로 채운 뒤 코딩):**

| 범주 | 항목 | 원본 실측값 | 재현값(치환 후) |
|---|---|---|---|
| 색 | 배경 / 본문 / 포인트 / 라인 | (hex) | (자사 톤) |
| 폰트 | 패밀리 / heading·body weight | | |
| 섹션 | 순서·개수 (전수 리스트) | | |
| 각 섹션 | 내부 구성(슬라이더/그리드/카드 수) | | |
| 인터랙션 | 종류(리빌/스냅/마퀴) + 근거 JS | | |
| **애니 속도** | 각 마퀴·슬라이더 duration(s) | | |
| 타이포 | 대형 텍스트 font-size / padding | | |
| 대형 브랜드텍스트 | 원본 문구 → **자사명 치환** | | |
| 이미지 | 각 슬롯 비율 / 개수 | | |
| 반응형 | 모바일 분기값(폰트·패딩) | | |

> 이 표가 곧 재현 명세서다. 코딩은 이 표를 "구현"하는 것이지 "발상"하는 게 아니다. **표에 없는 값을 코드에 넣었다면 그건 임의 생성이다 — 지우고 실측해서 채워라.**

## STEP E — 재현 검증 (실제 렌더로, 정적 파싱 금지)

재현물이 원본과 같은지 **실제 브라우저로 관찰**한다. HTML을 grep해 "클래스가 있으니 됐다"는 검증이 아니다.

### E-1. Playwright로 렌더·스크린샷·인터랙션 관찰

```bash
# 프로젝트 dir에서 (playwright가 로컬 node_modules에 있어야 import됨)
npm install --no-save playwright && npx playwright install chromium
```

```js
// 스크린샷 (리빌 애니메이션이 opacity:0로 가려지면 reduced-motion 강제)
import { chromium } from "playwright";
const b = await chromium.launch();
const p = await (await b.newContext({viewport:{width:1440,height:900}})).newPage();
await p.emulateMedia({ reducedMotion: "reduce" });  // reveal 즉시 표시 → 전체 콘텐츠 캡처
await p.goto(URL, { waitUntil: "domcontentloaded" }); // networkidle 금지(외부 폰트CDN이 안 끝남)
await p.waitForTimeout(700);
await p.screenshot({ path: "shot.png", fullPage: true });
await b.close();
```

- **스크린샷을 Read로 직접 눈으로 본다.** "빈 공백"이 보이면 리빌이 안 켜진 캡처 타이밍 문제일 수 있으니 `reducedMotion:"reduce"`로 재확인.
- **순환 슬라이더 검증:** `setTimeout` 간격으로 활성 슬라이드 텍스트를 여러 번 읽어 실제로 바뀌는지 관찰(정적으로 "슬라이드 4개 있음"은 순환 증명이 아니다).

### E-2. 모바일 가로 스크롤 (마퀴·슬라이더는 overflow 위험)

```js
for (const w of [360, 768]) {
  const ctx = await b.newContext({ viewport:{width:w,height:800} });
  const p = await ctx.newPage(); await p.goto(URL, {waitUntil:"domcontentloaded"});
  const ov = await p.evaluate(()=>document.documentElement.scrollWidth - document.documentElement.clientWidth);
  console.log(`[${w}] overflow=${ov}`); // 0이어야 통과. width:max-content 요소는 overflow:hidden 필수
}
```

## ⚠️ 반복된 함정 (이 세션에서 실제로 당한 것)

1. **주석에 벤치명이 샌다.** 재현하며 `// vos n_signature 재현` 같은 주석을 쓰면 css/js에 원본 상호가 박힌다 → **공개 서빙 파일이라 유출**(해체 프롬프트 §155). 주석에도 벤치명 쓰지 마라. 매 빌드 후 `grep -riE "vos|원본상호"` 재검사.
2. **원본 실명·상호가 이미지/텍스트에 있다.** vos 스크린샷에 원장 실명(`김홍석`)·`home_img2` 파일명이 있었다 → **절대 결과물에 넣지 마라**(규칙 11, 법적 사고). 플레이스홀더/자사명으로 치환.
3. **stale 서버가 옛 빌드를 서빙한다.** 이전 dev 서버가 포트를 물고 있으면 curl/스크린샷이 옛 결과를 보여줘 "미작동"으로 오판한다. 검증 전 `netstat -ano | grep :PORT`로 프로세스 확인 후 `taskkill`.
4. **`networkidle` 타임아웃.** 외부 폰트 CDN(Pretendard 등) 때문에 네트워크가 안 쉰다 → Playwright는 `domcontentloaded`로.
5. **개수를 grep 카운트만 믿지 마라.** 슬라이드가 한 컨테이너에 뭉치면 카운트 1로 보인다 → 제목/이미지 세트 수로 교차 확인.

## ★ 재현 완료 게이트 (원본과 나란히 대조)

재현 끝이라 판단하면, **원본 스크린샷과 재현물 스크린샷을 같은 섹션끼리 나란히 놓고 대조**한다(Playwright로 원본·재현물 각각 캡처). 아래가 전부 일치해야 완료:
- [ ] 섹션 순서·개수 동일 (누락 0)
- [ ] 각 섹션 내부 구성 동일 (슬라이더면 슬라이더, 카드 수 동일)
- [ ] 색·폰트·크기·간격이 SPEC SHEET 실측값과 일치
- [ ] 애니메이션 속도가 실측 duration과 일치 (`getComputedStyle` 확인)
- [ ] 대형 브랜드 텍스트 = 자사명 (원본 상호 유출 0)
- [ ] 모바일 360/768 가로스크롤 0
- [ ] 원본 상호·실명 grep 0건

**하나라도 어긋나면 "완료"라 말하지 마라.** 사용자가 스크린샷으로 반박하기 전에 스스로 대조해서 잡는다.
