> **목적:** 디자인 해체·프론트 구현에서 `[에셋 필요]`/"○○ 슬롯"으로 비워둔 이미지·영상을, 힉스필드 MCP로 생성해 채우는 플로우.
> **위치:** build.md STEP 3(프론트) 이후 ~ STEP 6(R2 업로드) 사이. 슬롯을 채운 뒤 R2에 올린다.

## ★ 0. 의료 이미지 안전 원칙 (가장 먼저)

의료 홈페이지 에셋은 **법적·신뢰 리스크**가 있다. AI 생성 가부를 반드시 구분한다.

| 에셋 종류 | AI 생성 | 이유 |
|---|---|---|
| 인테리어·공간 분위기컷 | ✅ OK | 실제 인물·결과 아님 |
| 시술 장비/제품 이미지 (추상·이미지컷) | ✅ OK | 브랜드·모델명 없는 일반 이미지면 무방 |
| 히어로 배경 영상 (분위기) | ✅ OK | 특정 인물·시술결과 아님 |
| 배경·패턴·아이콘 | ✅ OK | — |
| **원장 얼굴 사진** | ⚠️ **실사진 권장** | 가상 얼굴=허위 인물. E-E-A-T·의료 신뢰 훼손. 샘플 프로젝트에서만 가상 허용, 배포 시 실물 교체 |
| **시술 전후(비포/애프터) 사진** | ❌ **금지** | 실제 결과 아닌 가짜 = 의료광고법 위반 소지 |
| **환자·시술 장면** | ❌ 주의 | 실제로 오인될 이미지 금지 |

- **샘플/연습 프로젝트**: 가상 원장 얼굴까지 생성 가능하되, 문서·화면에 `[AI생성 가상 — 배포 전 실물 교체]` 명시.
- **실제 운영 홈페이지**: 원장·전후사진은 반드시 실사진. AI는 공간·분위기·배경만.

## 2. 모델 선택 (models_explore로 확정)

**규칙: 하드코딩하지 말고 `models_explore(action:'recommend')`로 목표+입력맥락 주고 추천받아라.** 모델은 자주 바뀐다.

실측 추천(2026-07, 인테리어 텍스트 프롬프트 기준):
- **인테리어·공간·제품컷**: `recraft_v4_1` (photorealistic, `model_type:utility`로 깔끔한 제품/목업, 비율 다양)
- **환경/배경**: `soul_location`
- **인물(원장 등)**: `soul_2` 계열 (portrait/editorial)
- **4K·텍스트 포함 이미지**: `nano_banana_pro`
- **영상(단일 시작프레임 애니)**: `kling3_0_turbo`, **정체성 유지**: `seedance_2_0`

`get_cost:true`로 생성 전 크레딧 미리 확인.

## 3. 프롬프트 규칙 (톤 일치가 핵심)

이 홈페이지는 **클린 블루(#1D5FCF) + 화이트 + 미니멀** 톤이다. 모든 에셋이 이 톤이어야 따로 놀지 않는다.

- 색: `colors` 파라미터(recraft)에 `#1D5FCF`, `#E8F0FD`, `#FFFFFF` 등 팔레트 지정
- 공통 프롬프트 접미: `clean minimal medical aesthetic, soft natural light, blue and white tone, premium dermatology clinic, no text, no logo, no brand names`
- **금지어 명시**: `no watermark, no clinic name, no korean text overlay` (원본 상호·글자 유입 방지)
- 비율은 슬롯 표의 값 그대로 (`aspect_ratio`)

**시술 이미지 프롬프트 예 (시그니처 6컷, 추상):**
- 여드름: `close-up of clean healthy skin texture, dermatology concept, blue tone, minimal`
- 리프팅: `abstract ultrasound/lifting device concept, sleek medical equipment, blue tone` (⚠️특정 브랜드 장비명 금지)
- 레이저토닝: `soft laser light on skin concept, glowing blue, minimal medical`

## 4. 실행 플로우

```
1) models_explore(recommend, goal+맥락)      → 모델 확정
2) generate_image({model, prompt, aspect_ratio, colors, get_cost:true})  → 비용 확인
3) generate_image(같은 params, get_cost 없이) → 생성
4) job_status / reveal_generation             → 결과 URL 확보
5) 톤·구도 확인 → 안 맞으면 프롬프트 수정 재생성 (검증 루프)
6) 확정 에셋 → R2 업로드(STEP 6) → media 테이블에 공개URL+alt
7) 프론트 슬롯을 <img src={R2url} alt="...">로 교체
```

- **alt는 실제 내용 설명으로** (파일명 아님) — GEO/접근성. 예: `alt="잭피부과 프리미엄 대기공간"`
- 슬롯 교체 후 **모바일 360/768 재검증**(이미지가 레이아웃 안 깨는지) + **상호명 grep 0건**(생성 이미지에 글자 안 박혔는지 육안).

## 5. 검증 (failable)

- [ ] 생성 이미지에 **원본 상호·글자·워터마크 없음** (육안 + 프롬프트에 no text/logo 넣었는지)
- [ ] 톤이 클린 블루와 일치 (따로 놀지 않음)
- [ ] 원장/전후 사진은 **AI 생성 안 함**(또는 샘플 표시), 실물 교체 체크리스트에 등록
- [ ] R2 공개 URL이 브라우저에서 열림
- [ ] alt가 실제 내용 설명
- [ ] 슬롯 교체 후 모바일 가로스크롤 0건

## 한 줄 요약

> **공간·분위기·제품컷·배경은 힉스필드로 톤 맞춰 생성해 슬롯을 채운다.**
> **원장 얼굴·시술 전후는 AI로 만들지 않는다(실사진). 생성물엔 글자·상호·워터마크가 없어야 하고, 톤은 클린 블루로 통일한다.**
