# 네이버 블로그 URL → GEO 칼럼 리라이팅 — 참고 구현 (샘플 치환본)

> **위치:** [02_관리자페이지_설계.md](02_관리자페이지_설계.md) **§7 "발행 워크플로(자동 발행 파이프라인)"의 실제 구현체.**
> 관리자 페이지에 네이버 블로그 URL을 붙여넣으면 → 글 목록 조회 → 선택 저장 → 3가지 모드로 리라이팅까지 수행하는 자립형 단일 파일 번들(서버 코어 + API 라우트 + React UI).
>
> **3가지 리라이팅 모드 ↔ 워크플로 매핑:**
> | 모드 | 하는 일 | 02 §7에서의 역할 |
> |------|---------|------------------|
> | `preserve` (원본 보존) | 말투·구조 보존 + 미세 다듬기 + 하단 실용 Q&A 추가 | 가벼운 각색 |
> | `seo-merge` (SEO 머지) | 구글 SERP 신호 추출 → AEO/GEO 구조로 재구성 (SERP API 없으면 preserve로 자동 fallback) | 검색 최적화 각색 |
> | `geo` (홈페이지 GEO 글) | 구조화 JSON(제목/슬러그/lede/핵심답변/TL;DR/섹션/Quote-ready/FAQ/용어정리) 생성 → 목차+진행바 포함 완성형 HTML 렌더 | **"AI 초안 생성" 버튼의 본체** |
>
> **Supabase 저장 연동 포인트 (04 참고구현과 연결) — ★저장 방식 확정 (상세는 02 §7.1):** `geo` 모드는 **완성형 HTML이 아니라 그 직전의 구조화 JSON(GeoArticle)** 을 [saveBlogWithJsonLd()](04_supabase_참고구현/lib/saveBlogWithJsonLd.ts) 단일 함수로 `status='draft'` 저장한다 (title/slug → 동명 컬럼, category → category_id FK, keyAnswer+tldr → excerpt, sections → sections_html JSONB, `faq` → `faqs` JSONB → 저장 시 buildJsonLd가 FAQPage 스키마 자동 조립, glossary → glossary 테이블 누적). 저장 함수가 JSON-LD를 `structured_data`에 자동으로 담으므로 별도 훅이 필요 없다. 아래 `renderGeoArticleHtml`의 HTML/CSS는 저장용이 아니라 **프론트 렌더러 컴포넌트의 참고 디자인**이다. 이렇게 하면 02 §7의 [초안 입수 → schema_content_match/author_identity_match 검수 → 발행] 흐름이 완성된다.
>
> **익명화:** 원본 파일(`홈페이지 벤치마킹/naver_rewriting.md`)에 있던 실제 의원 도메인·지역명은 샘플로 치환됨. 코드 로직은 원본 그대로.

/* ── 1-1. blogId 추출 ──────────────────────────────────────────────────── */

const RESERVED = new Set([
  'PostList.naver', 'PostView.naver', 'GoBlogWrite.naver',
  'PostTitleListAsync.naver', 'PostList', 'PostView',
]);

export function extractBlogId(input: string): string | null {
  if (!input) return null;
  const raw = input.trim();
  if (!raw) return null;

  // URL parsing path
  try {
    const url = new URL(raw.startsWith('http') ? raw : `https://${raw}`);
    const host = url.hostname.toLowerCase();
    if (host === 'blog.naver.com' || host === 'm.blog.naver.com') {
      // 1) ?blogId= query wins
      const q = url.searchParams.get('blogId');
      if (q && /^[A-Za-z0-9_-]+$/.test(q)) return q;
      // 2) /{blogId} or /{blogId}/{logNo}
      const seg = url.pathname.split('/').filter(Boolean)[0];
      if (seg && !RESERVED.has(seg) && /^[A-Za-z0-9_-]+$/.test(seg)) return seg;
    }
  } catch {}

  // Bare id fallback
  if (/^[A-Za-z0-9_-]+$/.test(raw)) return raw;
  return null;
}

/* ── 1-2. 네이버 비표준 JSON 정리 ──────────────────────────────────────── */

/**
 * 네이버 PostTitleListAsync.naver 응답은 표준 JSON 이 아니다.
 * pagingHtml 필드 안에 `\'` (백슬래시+작은따옴표) 같은 잘못된 이스케이프가 들어있어
 * JSON.parse 가 즉시 실패한다. JSON 규격상 허용되는 이스케이프 (\", \\, \/, \b, \f, \n, \r, \t, \uXXXX)
 * 외의 모든 backslash 를 제거한다.
 */
export function sanitizeNaverJson(text: string): string {
  return text.replace(/\\(?!["\\/bfnrtu])/g, '');
}

/* ── 1-3. 글 목록 가져오기 ─────────────────────────────────────────────── */

export interface NaverPostListItem {
  logNo: string;
  title: string;       // decoded
  addDate: string;     // "2026. 5. 27."
  url: string;         // PostView URL
}

export interface FetchPostListResult {
  posts: NaverPostListItem[];
  hasMore: boolean;
}

/**
 * 페이지당 30개. 네이버 비동기 API 가 30개 미만을 반환하면 hasMore=false.
 */
export async function fetchPostList(
  blogId: string,
  page = 1,
): Promise<FetchPostListResult> {
  const params = new URLSearchParams({
    blogId,
    viewdate: '',
    currentPage: String(page),
    categoryNo: '0',
    countPerPage: '30',
  });

  const doFetch = () =>
    fetch(`https://blog.naver.com/PostTitleListAsync.naver?${params}`, {
      headers: {
        Referer: 'https://blog.naver.com',
        'User-Agent': UA,
        'Accept-Encoding': 'identity',
        // NEVER send Origin — Naver returns 403 if present.
      },
    });

  let res = await doFetch();
  if (!res.ok && (res.status === 403 || res.status === 429)) {
    await new Promise((r) => setTimeout(r, 1000));
    res = await doFetch();
  }
  if (!res.ok) throw new Error(`naver http ${res.status}`);

  const raw = await res.text();
  let data: { resultCode?: string; postList?: { logNo: string; title: string; addDate: string }[] };
  try {
    data = JSON.parse(sanitizeNaverJson(raw));
  } catch (e) {
    throw new Error(`naver json parse failed: ${(e as Error).message}`);
  }

  if (data.resultCode !== 'S') {
    throw new Error('blogId 확인 필요 (resultCode !== S)');
  }

  const list = data.postList ?? [];
  return {
    posts: list.map((p) => ({
      logNo: p.logNo,
      title: decodeURIComponent(p.title.replace(/\+/g, ' ')),
      addDate: p.addDate,
      url: `https://blog.naver.com/PostView.naver?blogId=${blogId}&logNo=${p.logNo}`,
    })),
    hasMore: list.length === 30,
  };
}

/* ── 1-4. 본문 스크래핑 (HTML → 마크다운, 이미지 제외) ─────────────────── */

export interface ScrapedPost {
  title: string;
  markdown: string;
  publishedAt?: string;
}

async function getHtml(url: string): Promise<string> {
  const doFetch = () =>
    fetch(url, {
      headers: {
        Referer: 'https://blog.naver.com',
        'User-Agent': UA,
        'Accept-Encoding': 'identity',
      },
    });
  let res = await doFetch();
  if (!res.ok && (res.status === 403 || res.status === 429)) {
    await new Promise((r) => setTimeout(r, 1000));
    res = await doFetch();
  }
  if (!res.ok) throw new Error(`naver http ${res.status}`);
  return res.text();
}

/**
 * 네이버 블로그 글은 보통 외부 페이지에 iframe 으로 본문이 들어있다.
 *   <iframe id="mainFrame" src="/PostView.naver?...">  ← 실제 본문은 이 src 안
 * iframe 이 없으면 모바일 페이지나 새로 통합된 케이스이므로 본 페이지를 그대로 사용한다.
 */
async function resolveContentHtml(url: string): Promise<string> {
  const first = await getHtml(url);
  const $ = cheerio.load(first);
  const frame = $('iframe#mainFrame').attr('src');
  if (!frame) return first;
  const inner = frame.startsWith('http') ? frame : `https://blog.naver.com${frame}`;
  return await getHtml(inner);
}

/**
 * 호출당 새 turndown 인스턴스를 만든다. 이미지(<img>)는 결과물에 포함하지
 * 않으므로 전부 제거하는 룰을 등록한다.
 */
function createTurndown(): TurndownService {
  const td = new TurndownService({
    headingStyle: 'atx',
    bulletListMarker: '-',
    codeBlockStyle: 'fenced',
  });

  td.addRule('drop-images', {
    filter: 'img',
    replacement: () => '',
  });

  return td;
}

export async function scrapePost(url: string): Promise<ScrapedPost> {
  const html = await resolveContentHtml(url);
  const $ = cheerio.load(html);

  // 제목: SE3 (현행) 우선, 그 다음 SE2, 마지막 <meta og:title>
  const title =
    $('.se-title-text').first().text().trim() ||
    $('.pcol1').first().text().trim() ||
    $('meta[property="og:title"]').attr('content')?.trim() ||
    '제목 없음';

  // 본문 컨테이너 선택 (현행 SmartEditor One)
  const body =
    $('.se-main-container').first().html() ||
    $('#postViewArea').first().html() ||
    $('#viewTypeSelector').first().html() ||
    '';

  if (!body || body.trim().length < 20) {
    throw new Error('본문 컨테이너를 찾지 못했습니다. 글이 비공개이거나 구조가 다릅니다.');
  }

  const markdown = createTurndown().turndown(body).trim();

  // 작성일: SE3 의 <span class="se_publishDate"> 또는 og:article:published_time
  const publishedAt =
    $('.se_publishDate').first().text().trim() ||
    $('meta[property="article:published_time"]').attr('content') ||
    undefined;

  return { title, markdown, publishedAt };
}

/* ── 1-8. SEO 신호 추출 (선택적 — SEO 머지 모드 전용) ──────────────────── */

/**
 * 'SEO 머지' 모드가 사용하는 SERP 분석 내부 API 경로.
 * 대상 프로그램에 이 엔드포인트가 없으면 extractSeoSignals 가 null 을 반환하고
 * 리라이팅은 '원본 보존' 모드로 자동 fallback 된다 — 없어도 전체 기능은 동작한다.
 * (원본 프로젝트에서는 DataForSEO 기반 구글 SERP 상위 결과를 반환하는 API 였다.
 *  응답 형식: { success, data: { serpResults: [{ title, snippet }] } })
 */
const SERP_ANALYSIS_PATH = '/api/serp-analysis';

export interface SeoSignals {
  keyword: string;
  topKeywords: string[];
  topH2Topics: string[];
  avgLength: number;
}

/**
 * SERP 상위 결과의 title+snippet 를 gpt-4o-mini 로 압축.
 * SERP API 없음·SERP 0건·추출 실패 → null 반환 (호출자가 preserve fallback).
 */
export async function extractSeoSignals(
  keyword: string,
  openaiKey: string,
  origin: string,
): Promise<SeoSignals | null> {
  try {
    const serpRes = await fetch(`${origin}${SERP_ANALYSIS_PATH}`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ keyword }),
    });
    if (!serpRes.ok) return null;

    const serp = (await serpRes.json()) as {
      success?: boolean;
      data?: { serpResults?: { title?: string; snippet?: string }[] };
    };
    const items = (serp.data?.serpResults ?? []).slice(0, 10);
    if (items.length === 0) return null;

    const corpus = items
      .map((r, i) => `${i + 1}. ${r.title ?? ''}\n${r.snippet ?? ''}`)
      .join('\n\n');

    const openai = new OpenAI({ apiKey: openaiKey });
    const res = await openai.chat.completions.create({
      model: 'gpt-4o-mini',
      response_format: { type: 'json_object' },
      messages: [
        {
          role: 'system',
          content:
            '구글 상위 노출 글들의 제목+스니펫을 읽고, 공통 보조 키워드 8개, 공통 H2 토픽 5개, 평균 단어 수 추정치를 JSON 으로 추출하라. ' +
            '응답 형식: {"topKeywords":["..."],"topH2Topics":["..."],"avgLength":1200}',
        },
        { role: 'user', content: corpus },
      ],
    });

    const parsed = JSON.parse(res.choices[0].message.content ?? '{}');
    return {
      keyword,
      topKeywords: Array.isArray(parsed.topKeywords) ? parsed.topKeywords : [],
      topH2Topics: Array.isArray(parsed.topH2Topics) ? parsed.topH2Topics : [],
      avgLength: typeof parsed.avgLength === 'number' ? parsed.avgLength : 1500,
    };
  } catch {
    return null;
  }
}

## 0. 용어 정리 (먼저 알고 시작)

| 용어 | 정의 | 목표 |
|------|------|------|
| **SEO** | 검색 엔진 최적화 | 검색 결과 "파란 링크" 상위 노출 → 클릭 유도 |

## 3. 글 쓰기 전 — 기획 단계

- [ ] **키워드가 아니라 "질문"에서 출발**한다. 사용자가 ChatGPT/Gemini에 실제로 입력하는 프롬프트를 수집한다.
  - 예: "강아지 분리불안 해결법" (X 키워드) → "강아지가 혼자 있을 때 짖는 걸 어떻게 멈추나요?" (O 질문)
- [ ] 하나의 글 = 하나의 명확한 사용자 의도(intent)에 집중한다.
- [ ] 글 제목·소제목을 **실제 검색 질문 형태**("~란?", "~하는 법", "~와 ~의 차이")로 설계한다.
- [ ] 경쟁 콘텐츠를 AI에 직접 질문해보고, **현재 누가 인용되는지** 파악한다.

## 4. 글 구조 — AI가 발췌하기 쉬운 형태

### 4-1. BLUF / 50단어 규칙 (가장 중요)
- 모든 페이지와 주요 섹션은 **첫 40~60자(한국어 기준 약 2~3문장) 안에 완결된 핵심 답변**을 제시한다.
- AI는 소제목 바로 다음 **1~2문장을 가장 자주 인용**한다 → 결론을 먼저(Bottom Line Up Front), 근거는 뒤에.

### 4-2. TL;DR 요약 박스
- 글 최상단에 3~5줄 핵심 요약(TL;DR)을 배치한다.

### 4-3. 헤딩 구조
- H2 대제목 3~4개, 각 H2 아래 H3 소제목 2~4개.
- 헤딩은 모호한 제목 대신 **핵심 결론을 요약하는 문장형**으로 작성.
  - (X) "특징" → (O) "분리불안의 3가지 핵심 신호"

### 4-4. Q&A 섹션
- "자주 묻는 질문" 형태의 Q&A는 LLM 청킹(chunking)에 가장 적합한 형식이다.
- 질문은 H2/H3로, 답변 첫 문장에 정답을 바로 배치.

### 4-5. 발췌 친화 요소
- [ ] **표(table)**: 비교·정리 데이터는 표로. AI가 구조화된 사실로 추출하기 쉽다.
- [ ] **번호/불릿 리스트**: 단계·항목은 리스트로.
- [ ] **데이터 블록**: 통계는 한 문장에 명확히.

## 5. 본문 작성 — 문장 단위 규칙

- [ ] **시맨틱 트리플(주어-동사-목적어)** 형태로 사실을 진술한다. AI가 지식 그래프에 그대로 흡수한다.
  - 예: "비타민 D는 칼슘 흡수를 돕는다." (명확한 사실 문장)
- [ ] 모든 핵심 주장에 **통계 / 인용구 / 출처** 중 하나 이상 부착 (2장 규칙).
- [ ] 출처는 **명시적으로**: "Gartner의 2025년 전망에 따르면…" 처럼 근거 없는 주장보다 출처 있는 주장이 AI 신뢰를 받는다.
- [ ] 가독성: 문단을 짧게, 논리적 전환을 명확히, "문제 → 해결" 흐름으로 전개.
- [ ] 모호함 제거: 대명사 남발 금지, 각 문장이 독립적으로 이해되도록(청크 단위로 발췌되므로).
- [ ] 날짜·수치·고유명사를 정확히 — AI는 검증 가능한 구체 정보를 선호한다.

## 6. E-E-A-T · 권위 신호 (신뢰도)

AI는 "이 소스를 인용해도 되는가"를 판단한다. 권위 신호를 명시하라.

- [ ] **저자 정보 노출**: 작성자 이름 + 전문성/자격 + 프로필.
- [ ] **발행일 + 수정일**을 명확히 표기 (신선도가 인용 확률에 직결).
- [ ] **1차 경험/데이터**(Experience): 직접 실험·사용·사례 등 고유 정보 포함.
- [ ] 외부 권위 매체 언급·피인용 확보(브랜드 신뢰 축적).
- [ ] 출처 링크를 신뢰할 수 있는 기관·연구로 연결.

/** 제목 → 슬러그: 첫 구분자(쉼표 등) 앞 핵심 키워드만 남기고 공백·특수문자 제거 */
export function deriveSlug(title: string): string {
  const core = title.split(/[,，?？!！:：]/)[0] ?? title;
  const slug = core.replace(/[^0-9A-Za-z가-힣]/g, '');
  return slug || title.replace(/[^0-9A-Za-z가-힣]/g, '');
}

function escapeHtml(s: string): string {
  return s
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;');
}

/** GPT 가 생성한 섹션 HTML 조각의 위험 요소만 제거 (script, 인라인 이벤트) */
function sanitizeSectionHtml(html: string): string {
  return html
    .replace(/<script[\s\S]*?<\/script>/gi, '')
    .replace(/\son\w+="[^"]*"/gi, '');
}

/** GPT JSON 응답을 검증·보정. 이미지 0장이면 첫 섹션에 placeholder 주입. */
// eslint-disable-next-line @typescript-eslint/no-explicit-any
export function normalizeGeoArticle(raw: any, fallbackTitle: string): GeoArticle {
  const title: string =
    typeof raw?.title === 'string' && raw.title.trim() ? raw.title.trim() : fallbackTitle;
  const slugSrc: string =
    typeof raw?.slug === 'string' && raw.slug.trim() ? raw.slug : title;
  const slug = slugSrc.replace(/[^0-9A-Za-z가-힣]/g, '') || deriveSlug(title);

  const sections: GeoArticleSection[] = (Array.isArray(raw?.sections) ? raw.sections : [])
    // eslint-disable-next-line @typescript-eslint/no-explicit-any
    .filter((s: any) => s && typeof s.heading === 'string' && typeof s.html === 'string')
    // eslint-disable-next-line @typescript-eslint/no-explicit-any
    .map((s: any) => ({
      heading: s.heading,
      html: s.html,
      image:
        s.image && typeof s.image.filename === 'string'
          ? {
              filename: s.image.filename,
              alt: typeof s.image.alt === 'string' ? s.image.alt : title,
              caption: typeof s.image.caption === 'string' ? s.image.caption : '',
            }
          : undefined,
    }));
  if (sections.length === 0) throw new Error('GEO 글 생성 실패: sections 가 비어있습니다');

  // 이미지 최소 1장 보장
  if (!sections.some((s) => s.image)) {
    sections[0].image = {
      filename: 'image-01.png',
      alt: title,
      caption: '본문 관련 이미지를 업로드해 주세요.',
    };
  }

  const strArr = (v: unknown): string[] =>
    Array.isArray(v) ? v.filter((x): x is string => typeof x === 'string') : [];

  return {
    title,
    slug,
    category: typeof raw?.category === 'string' && raw.category.trim() ? raw.category.trim() : '칼럼',
    lede: typeof raw?.lede === 'string' ? raw.lede : '',
    keyAnswer: typeof raw?.keyAnswer === 'string' ? raw.keyAnswer : '',
    tldr: strArr(raw?.tldr),
    sections,
    quoteReady: {
      conclusion: typeof raw?.quoteReady?.conclusion === 'string' ? raw.quoteReady.conclusion : '',
      reason: typeof raw?.quoteReady?.reason === 'string' ? raw.quoteReady.reason : '',
      example: typeof raw?.quoteReady?.example === 'string' ? raw.quoteReady.example : '',
      caution: typeof raw?.quoteReady?.caution === 'string' ? raw.quoteReady.caution : '',
    },
    faq: (Array.isArray(raw?.faq) ? raw.faq : [])
      // eslint-disable-next-line @typescript-eslint/no-explicit-any
      .filter((f: any) => f && typeof f.q === 'string' && typeof f.a === 'string'),
    glossary: (Array.isArray(raw?.glossary) ? raw.glossary : [])
      .filter(
        // eslint-disable-next-line @typescript-eslint/no-explicit-any
        (g: any) =>
          g && typeof g.term === 'string' && typeof g.definition === 'string',
      )
      // eslint-disable-next-line @typescript-eslint/no-explicit-any
      .map((g: any) => ({
        term: g.term,
        definition: g.definition,
        easy: typeof g.easy === 'string' ? g.easy : '',
      })),
  };
}

function json(data: unknown, status = 200): Response {
  return new Response(JSON.stringify(data), {
    status,
    headers: { 'Content-Type': 'application/json' },
  });
}

/* ── 2-1. POST /api/naver-import/list — 글 목록 ────────────────────────── */

export async function handleListRequest(req: Request): Promise<Response> {
  try {
    const body = await req.json();
    const blogUrl: string = typeof body?.blogUrl === 'string' ? body.blogUrl : '';
    const page: number = Number.isInteger(body?.page) && body.page > 0 ? body.page : 1;

    const blogId = extractBlogId(blogUrl);
    if (!blogId) {
      return json({ error: '네이버 블로그 URL 에서 blogId를 추출하지 못했습니다.' }, 400);
    }

    const { posts, hasMore } = await fetchPostList(blogId, page);
    return json({
      blogId,
      posts,
      hasMore,
      nextPage: hasMore ? page + 1 : null,
    });
  } catch (err) {
    const msg = err instanceof Error ? err.message : 'unknown error';
    const status = msg.includes('blogId 확인 필요') ? 400 : 502;
    return json({ error: msg }, status);
  }
}

/* ── 2-3. POST /api/naver-import/rewrite — GPT 리라이팅 (SSE 스트림) ───── */

export interface RewriteBody {
  sourceUrl: string;
  mode: 'preserve' | 'seo-merge' | 'geo';
  keyword?: string;
  openaiKey: string;
}

function sseEncoder(controller: ReadableStreamDefaultController) {
  const enc = new TextEncoder();
  return (event: string, data: unknown) => {
    controller.enqueue(enc.encode(`event: ${event}\ndata: ${JSON.stringify(data)}\n\n`));
  };
}

function splitTitleAndBody(markdown: string): { title: string; body: string } {
  // strip leading/trailing code fences
  const md = markdown.trim().replace(/^```(?:markdown)?\s*\n?/i, '').replace(/\n?```\s*$/i, '');
  const m = md.match(/^#\s+(.+?)\n([\s\S]*)$/);
  if (!m) return { title: '', body: md };
  return { title: m[1].trim(), body: m[2].trim() };
}

export async function handleRewriteRequest(req: Request): Promise<Response> {
  const body = (await req.json()) as RewriteBody;
  const { sourceUrl, mode, openaiKey } = body;

  return new Response(
    new ReadableStream({
      async start(controller) {
        const send = sseEncoder(controller);
        try {
          if (!sourceUrl) throw new Error('sourceUrl is required');
          if (!openaiKey) throw new Error('OpenAI key is required');
          if (mode === 'seo-merge' && !body.keyword) {
            throw new Error('SEO_MERGE 모드는 keyword 필수');
          }

          send('stage', { message: '원본 글 가져오는 중...' });
          const post = await scrapePost(sourceUrl);

          // ── 홈페이지 GEO 글 모드: 구조화 JSON 생성 → 완성형 HTML 렌더 ──
          if (mode === 'geo') {
            send('stage', { message: 'GEO 칼럼 구조화 요청 중 (GPT)...' });
            const openai = new OpenAI({ apiKey: openaiKey });
            const res = await openai.chat.completions.create({
              model: 'gpt-4o-2024-08-06',
              response_format: { type: 'json_object' },
              messages: [
                { role: 'system', content: buildGeoSystemPrompt() },
                { role: 'user', content: buildGeoUserPrompt(post.markdown) },
              ],
              temperature: 0.5,
            });

            send('stage', { message: 'HTML 렌더링 중...' });
            const article = normalizeGeoArticle(
              JSON.parse(res.choices[0].message.content ?? '{}'),
              post.title,
            );
            const html = renderGeoArticleHtml(article);

            send('complete', {
              title: article.title,
              slug: article.slug,
              html,
              markdown: html,
              sourceUrl,
            });
            return;
          }

          // Resolve final mode first (seo-merge may fall back to preserve),
          // then build the matching system prompt — preserve must NOT get the
          // AEO/GEO doc + structural rules in its system prompt.
          let userPrompt: string;
          let resolvedMode: 'preserve' | 'seo-merge' = mode;
          if (mode === 'seo-merge') {
            send('stage', { message: '구글 상위노출 SEO 신호 추출 중...' });
            const origin = new URL(req.url).origin;
            const signals = await extractSeoSignals(body.keyword!, openaiKey, origin);
            if (!signals) {
              send('stage', { message: 'SEO 신호 추출 실패 — 모드 A 로 fallback' });
              userPrompt = buildUserPrompt('preserve', post.markdown);
              resolvedMode = 'preserve';
            } else {
              send('stage', { message: `SEO 신호 확보: 보조 ${signals.topKeywords.length}개, H2 ${signals.topH2Topics.length}개` });
              userPrompt = buildUserPrompt('seo-merge', post.markdown, signals);
              resolvedMode = 'seo-merge';
            }
          } else {
            userPrompt = buildUserPrompt(mode, post.markdown);
            resolvedMode = 'preserve';
          }

          send('stage', {
            message: resolvedMode === 'preserve'
              ? '보존 모드 프롬프트 구성...'
              : 'AEO/GEO 지침 로딩...',
          });
          const systemPrompt = buildSystemPrompt(resolvedMode);

          send('stage', { message: 'GPT 리라이팅 시작...' });
          const openai = new OpenAI({ apiKey: openaiKey });
          const stream = await openai.chat.completions.create({
            model: 'gpt-4o-2024-08-06',
            stream: true,
            messages: [
              { role: 'system', content: systemPrompt },
              { role: 'user', content: userPrompt },
            ],
            temperature: 0.6,
          });

          let full = '';
          for await (const chunk of stream) {
            const delta = chunk.choices[0]?.delta?.content ?? '';
            if (delta) {
              full += delta;
              send('chunk', { text: delta });
            }
          }

          const { title, body: rewriteBody } = splitTitleAndBody(full);
          const finalTitle = title || post.title;
          const finalMarkdown = `${rewriteBody}\n\n---\n> 원본: [${post.title}](${sourceUrl})`;

          send('complete', {
            title: finalTitle,
            markdown: finalMarkdown,
            sourceUrl,
          });
        } catch (err) {
          const msg = err instanceof Error ? err.message : 'unknown error';
          send('error', { error: msg });
        } finally {
          controller.close();
        }
      },
    }),
    {
      headers: {
        'Content-Type': 'text/event-stream',
        'Cache-Control': 'no-cache',
        Connection: 'keep-alive',
      },
    },
  );
}

const SAVED_POSTS_KEY = 'naverImportPosts';

/* ── 3-1. 내장 미니 토스트 ─────────────────────────────────────────────── */

interface ToastItem { id: number; type: 'success' | 'error'; message: string }

function useMiniToast() {
  const [toasts, setToasts] = useState<ToastItem[]>([]);

  const push = useCallback((type: 'success' | 'error', message: string) => {
    const id = Date.now() + Math.random();
    setToasts((prev) => [...prev, { id, type, message }]);
    setTimeout(() => setToasts((prev) => prev.filter((t) => t.id !== id)), 3500);
  }, []);

  const node = (
    <div className="fixed bottom-4 right-4 z-[100] space-y-2">
      {toasts.map((t) => (
        <div
          key={t.id}
          className={`px-4 py-2 rounded-lg text-sm text-white shadow-lg ${
            t.type === 'success' ? 'bg-green-600' : 'bg-red-600'
          }`}
        >
          {t.message}
        </div>
      ))}
    </div>
  );

  return {
    success: (m: string) => push('success', m),
    error: (m: string) => push('error', m),
    node,
  };
}

/* ── 3-2. 저장 목록 (localStorage) ─────────────────────────────────────── */

function useSavedPosts() {
  const [saved, setSaved] = useState<SavedNaverPost[]>([]);
  const [hydrated, setHydrated] = useState(false);

  useEffect(() => {
    try {
      const raw = localStorage.getItem(SAVED_POSTS_KEY);
      if (raw) {
        const parsed = JSON.parse(raw);
        if (Array.isArray(parsed)) setSaved(parsed);
      }
    } catch {}
    setHydrated(true);
  }, []);

  useEffect(() => {
    if (!hydrated) return;
    try { localStorage.setItem(SAVED_POSTS_KEY, JSON.stringify(saved)); } catch {}
  }, [saved, hydrated]);

  const addPosts = useCallback((posts: Omit<SavedNaverPost, 'id' | 'savedAt'>[]) => {
    let added = 0;
    setSaved((prev) => {
      const seen = new Set(prev.map((p) => `${p.blogId}::${p.logNo}`));
      const next = [...prev];
      for (const p of posts) {
        const key = `${p.blogId}::${p.logNo}`;
        if (seen.has(key)) continue;
        seen.add(key);
        next.push({ ...p, id: crypto.randomUUID(), savedAt: Date.now() });
        added++;
      }
      return next;
    });
    return added;
  }, []);

  const removePost = useCallback((id: string) => {
    setSaved((prev) => prev.filter((p) => p.id !== id));
  }, []);

  return { saved, addPosts, removePost };
}

export default function NaverImportPage() {

  const [page, setPage] = useState(1);
  const [items, setItems] = useState<ListItem[]>([]);
  const [hasMore, setHasMore] = useState(false);
  const [loading, setLoading] = useState(false);
  const [checked, setChecked] = useState<Set<string>>(new Set());

  const [openaiKey, setOpenaiKey] = useState('');
  const [rewriteTarget, setRewriteTarget] = useState<SavedNaverPost | null>(null);
  const [rewriteMode, setRewriteMode] = useState<'preserve' | 'seo-merge' | 'geo'>('preserve');
  const [rewriteKeyword, setRewriteKeyword] = useState('');
  const [rewriting, setRewriting] = useState(false);
  const [rewriteLogs, setRewriteLogs] = useState<string[]>([]);
  const [rewriteResult, setRewriteResult] = useState<{
    title: string; markdown: string; sourceUrl: string; slug?: string; html?: string;
  } | null>(null);

  useEffect(() => {
    // 원본 프로젝트는 /inblog 설정 화면이 이 키에 OpenAI Key 를 저장했다.

    try {

      }
    } catch {}
  }, []);

  const fetchPage = async (nextPage: number, append: boolean) => {
    setLoading(true);
    try {
      const res = await fetch('/api/naver-import/list', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ blogUrl, page: nextPage }),
      });
      const data = await res.json();
      if (!res.ok) throw new Error(data?.error ?? '목록을 가져오지 못했습니다');
      setBlogId(data.blogId);
      setItems((prev) => (append ? [...prev, ...data.posts] : data.posts));

      toast.error(e instanceof Error ? e.message : '오류');
    } finally {
      setLoading(false);
    }
  };

  };

  const onMore = () => fetchPage(page + 1, true);

  const toggle = (logNo: string) => {
    setChecked((prev) => {
      const next = new Set(prev);
      if (next.has(logNo)) next.delete(logNo); else next.add(logNo);
      return next;
    });
  };

  const onSave = () => {
    const picked = items.filter((it) => checked.has(it.logNo));
    if (picked.length === 0) { toast.error('체크된 글이 없습니다'); return; }
    const added = addPosts(
      picked.map((p) => ({
        blogId,
        logNo: p.logNo,
        url: p.url,
        title: p.title,
        publishedAt: p.addDate,
      })),
    );
    toast.success(`${added}개 저장됨 (중복 ${picked.length - added}개 제외)`);
    setChecked(new Set());
  };

  const startRewrite = async () => {
    if (!rewriteTarget) return;
    if (!openaiKey) { toast.error('OpenAI API Key 를 입력하세요'); return; }
    if (rewriteMode === 'seo-merge' && !rewriteKeyword.trim()) {
      toast.error('SEO 머지 모드는 키워드 입력이 필요합니다');

    setRewriting(true);
    setRewriteLogs([]);

    try {
      const res = await fetch('/api/naver-import/rewrite', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          sourceUrl: rewriteTarget.url,
          mode: rewriteMode,
          keyword: rewriteMode === 'seo-merge' ? rewriteKeyword.trim() : undefined,
          openaiKey,
        }),
      });
      if (!res.body) throw new Error('스트림 응답 없음');

      const reader = res.body.getReader();
      const decoder = new TextDecoder();
      let buf = '';

        title: string; markdown: string; sourceUrl: string; slug?: string; html?: string;

      while (true) {
        const { value, done } = await reader.read();
        if (done) break;
        buf += decoder.decode(value, { stream: true });

        buf = events.pop() ?? '';
        for (const ev of events) {

          const eventLine = lines.find((l) => l.startsWith('event: '));

      //      }));

      await navigator.clipboard.writeText(
        rewriteResult.html ?? `# ${rewriteResult.title}\n\n${rewriteResult.markdown}`,
      );
      toast.success('클립보드에 복사됨');

    }

      <div className="max-w-5xl mx-auto space-y-6">
        <h1 className="text-2xl font-bold">네이버 글 불러오기</h1>

        {/* 1. URL 입력 */}

          <label className="block text-sm font-medium">네이버 블로그 URL</label>
          <div className="flex gap-2">

              placeholder="예: https://blog.naver.com/naver_diary"

            />
            <button

            )}

            {rewriting && (
              <ul className="text-xs text-gray-400 space-y-0.5 max-h-32 overflow-y-auto bg-gray-800/50 p-2 rounded">
                {rewriteLogs.map((l, i) => <li key={i}>· {l}</li>)}
              </ul>
            )}

            <div className="flex gap-2 justify-end">
              <button onClick={() => setRewriteTarget(null)} disabled={rewriting} className="px-4 py-2 bg-gray-700 hover:bg-gray-600 rounded">
                닫기
              </button>
              <button onClick={startRewrite} disabled={rewriting} className="px-4 py-2 bg-purple-600 hover:bg-purple-500 disabled:opacity-50 rounded font-medium">
                {rewriting ? '리라이팅 중...' : '리라이팅 시작'}
              </button>
            </div>
          </div>
        </div>
      )}

      {/* 리라이팅 결과 모달 */}
      {rewriteResult && (
        <div className="fixed inset-0 bg-black/70 flex items-center justify-center z-50 p-4">
          <div className="bg-gray-900 rounded-xl p-6 max-w-5xl w-full space-y-4">
            <h3 className="text-lg font-bold">리라이팅 결과</h3>
            <p className="text-sm font-medium">{rewriteResult.title}</p>
            {rewriteResult.slug && (
              <p className="text-sm text-gray-400">
                슬러그: <span className="text-pink-400 font-mono">/{rewriteResult.slug}</span>
              </p>
            )}
            {rewriteResult.html ? (
              <>
                <iframe
                  srcDoc={rewriteResult.html}
                  sandbox="allow-scripts"
                  title="GEO 칼럼 미리보기"
                  className="w-full h-[55vh] bg-white rounded"
                />
                <textarea
                  readOnly
                  value={rewriteResult.html}
                  className="w-full h-28 px-3 py-2 rounded bg-gray-800 border border-gray-700 text-xs font-mono resize-none"
                />
              </>
            ) : (
              <textarea
                readOnly
                value={rewriteResult.markdown}
                className="w-full h-[50vh] px-3 py-2 rounded bg-gray-800 border border-gray-700 text-sm font-mono resize-none"
              />
            )}
            <div className="flex gap-2 justify-end">
              <button onClick={copyResult} className="px-4 py-2 bg-blue-600 hover:bg-blue-500 rounded font-medium">
                {rewriteResult.html ? 'HTML 복사' : '마크다운 복사'}
              </button>
              <button onClick={() => setRewriteResult(null)} className="px-4 py-2 bg-gray-700 hover:bg-gray-600 rounded">
                닫기
              </button>
            </div>
          </div>
        </div>
      )}

      {toast.node}
    </div>
  );
}

## 부록 D. 리라이팅 LLM·geo 프롬프트 — 실전 보강 (검증본, 2026-07-13)

> 잭피부과 구축(`jackskin-geo`)에서 이 문서의 geo 모드를 실제 네이버 피부과 블로그 글로 돌려보며

### D-1. ★ 리라이팅 LLM = Gemini Flash 확정 (GPT-4o 탈락)

같은 원글(피부과 네이버 글, 본문 4,848자)·같은 프롬프트로 실측 비교한 결과:

| | GPT-4o (json_object) | **Gemini 3.5 Flash (responseMimeType: json)** |
|---|---|---|
| 제목 키워드 | ❌ **"마포피부과"를 "반포피부과"로 환각** | ✅ 원형 보존 |
| 본문 분량 | 726자 = **원본의 15%** (절대 글자수를 지시해도 압축) | **5,732자 = 원본의 118%** |
| 섹션 | 5개 × 120~190자 (뼈대만) | 7개 × 630~960자 (원본 디테일 전부) |

**원인:** GPT-4o는 JSON 강제 출력 모드에서 장문 한국어 생성을 회피하는 성향이 강하다.
"섹션당 최소 250자", "합계 3,900자 이상" 같은 절대 숫자를 프롬프트에 넣어도 15~27% 수준으로 압축했고,
지역명(타겟 키워드의 핵심)까지 왜곡했다. Gemini는 같은 프롬프트의 보존 규칙을 그대로 따랐다.

**결론: 원본 보존형 GEO 재가공(이 문서의 geo 모드)에는 Gemini 3.5 Flash를 쓴다.**
- ★ **API 모델 ID = `gemini-3.5-flash`** (@google/generative-ai `getGenerativeModel({ model })`). "3.5 Flash"라고만 적으면 구축 시 `gemini-2.0-flash` 등으로 오입력하기 쉬우니 정확한 ID를 못박는다. 키로 `GET /v1beta/models`(헤더 `x-goog-api-key`) 조회해 `generateContent` 지원 여부 확인 후 사용(모델 세대는 시간이 지나며 바뀔 수 있음 — 없으면 최신 flash로 교체하되 Flash 계열 유지). 린 피부과 구축(2026-07) 시 gemini-3.5-flash 호출 가능 확인.
- 호출 파라미터: `responseMimeType: 'application/json'`, `temperature: 0.5`, `maxOutputTokens: 32768`
- 키는 서버 환경변수(`GEMINI_API_KEY`)로만 — 운영자가 브라우저에 키를 입력하는 UI는 제거
- 참고 구현: `jackskin-geo/packages/geo-core/src/gemini.ts`

| # | 원본 규칙 | 실측 문제 | 개정 |

원본 프롬프트의 slug 규칙("한글 유지")으로 생성된 `naver프라이버시챌린지` 같은 한글 slug 는

### D-5. 발행 2경로 — 바로 발행 / 검수 저장

02 §7 워크플로의 실전 구현에서는 리라이팅 결과 화면에 버튼을 2개 둔다:
- **바로 발행**: `status=published` + `publishedAt=now` 로 저장 → 즉시 칼럼 노출
- **초안 저장 (검수)**: `status=draft` → 관리자가 `schemaContentMatch`·`authorIdentityMatch` 검수 후 발행
자동 발행 스케줄러의 `mode`(자동/검수)와 동일한 이분법이며, 초기 운영은 검수 경로를 권장한다 (02 §7.2).

### D-6. ★ sections_html 렌더링 — 블록을 `<p>`로 감싸지 마라 (표 깨짐·하이드레이션 에러)

**실측 버그 (린 피부과, 2026-07):** GeoArticle의 `sections`(각 `{heading, html}`)를 공개 페이지·관리자 미리보기에서 렌더할 때,
본문을 줄바꿈으로 쪼개 **각 줄을 `<p>{line}</p>`로 감쌌더니**, `<table>…</table>`이 통째로 든 줄이 `<p><table>…</table></p>`가 됐다.
HTML 규격상 `<p>` 안에는 블록 요소(`table`·`ul`·`div`)를 넣을 수 없어 → **① React 하이드레이션 에러(콘솔 "1 error") ② 브라우저가 DOM을 강제로 재구성하며 표가 뭉개짐.**

**해결 원칙:**
- 섹션 html은 **이미 완결된 HTML 블록**(`<p>`, `<table>`, `<ul>`을 포함)이다. **절대 `<p>`로 다시 감싸지 말고**, `<div dangerouslySetInnerHTML>` 또는 섹션 `<section>` 컨테이너에 **그대로 삽입**한다.
- 저장은 `sections_html`(구조화 배열 `[{heading, html}]`)을 정본으로 두고, 렌더 시 `heading → <h2>`, `html → 컨테이너에 그대로`. `content.text`(마크다운 합본)는 폴백/검색용 보조로만.
- 허용 태그(프롬프트에서 지정): `p, strong, em, ul, ol, li, table, thead, tbody, tr, th, td`. 렌더러 CSS에 이 태그들(특히 `table/th/td` 격자선, 모바일 `overflow-x:auto`) 스타일을 반드시 넣는다 — 없으면 표 칸이 붙어 나와 "표가 안 만들어진 것처럼" 보인다.

### D-7. 이미지 정책 — 크롤 단계에서 제외, 관리자가 검수 후 삽입

**크롤러(`scrapePost`)는 `<img>`를 전부 제거한다** (turndown `drop-images` 룰). 이유 2가지:
1. **핫링크 불안정:** 네이버 이미지는 `postfiles.pstatic.net` 등 네이버 CDN에 있어, 외부(우리 도메인)에서 직접 참조하면 네이버가 차단하거나 URL이 바뀌어 깨진다.
2. **저작권·의료광고:** 본인 블로그라도 이미지에 **환자 실사진·전후사진·워터마크·타 병원 로고**가 섞일 수 있다 — 그대로 홈페이지에 올리면 개인정보·의료광고법 위반. (본 문서 상단 "원본 워터마크·환자 실사진 재사용 금지"와 동일 원칙.)

→ 따라서 GEO 변환은 **텍스트만 안전하게** 가져오고, 이미지는 **관리자가 미디어 라이브러리(02 §5, R2)에서 검수한 자산을 직접 삽입**하거나 자체 생성(힉스필드 등) 이미지로 채운다. GeoArticle 스키마에 `sections[].image`(filename/alt/caption) 슬롯은 있으나, 이는 "이미지 자리 안내"일 뿐 원본 바이너리를 옮기는 통로가 아니다. (원본 이미지 자동 이관이 필요하면 별도로 R2 재업로드 파이프라인을 붙이되, 위 저작권 검수를 반드시 사람이 거치게 한다.)
