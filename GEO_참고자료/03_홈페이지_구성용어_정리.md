# 홈페이지 구성 용어 정리 (샘플 치환본)

> **용도:** 홈페이지 화면을 이루는 부분들의 이름을 초보자 눈높이로 정리. 각 용어마다 "무엇인지 → 어디 있는지 → 샘플 코드"를 함께 제공. 요구사항 대화·화면 설계 시 공통 언어로 사용.
> **익명화:** 예시의 상호·주소·전화·도메인은 전부 샘플 값(샘플치과, 000-0000-0000 등).

---

## 0. 한 장으로 보는 페이지 구조

```
┌─────────────────────────────────────────────┐
│  HEADER (헤더)  — 로고 | 메뉴(GNB) | 검색/전화  │  ← 모든 페이지 상단 공통
├─────────────────────────────────────────────┤
│                                             │
│   HERO (히어로)  — 큰 제목 + 한 줄 소개 + CTA   │  ← 첫 화면, 가장 눈에 띄는 영역
│                                             │
├─────────────────────────────────────────────┤
│   SECTION (섹션)  — 서비스안내 / 전문가 / 후기…  │  ← 본문, 여러 개가 세로로 쌓임
│   SECTION (섹션)  — FAQ …                     │
├─────────────────────────────────────────────┤
│  FOOTER (푸터)  — 주소·전화·사업자정보·키워드링크 │  ← 모든 페이지 하단 공통
└─────────────────────────────────────────────┘
```

---

## 1. 큰 골격 (모든 페이지 공통)

### 헤더 (Header)
- **무엇:** 페이지 맨 위 띠. 보통 로고 + 메뉴 + 전화/예약 버튼.
- **어디:** 모든 페이지 최상단에 고정 (스크롤해도 따라오면 "sticky header").
- **샘플:**
```html
<header>
  <img src="/logo.png" alt="샘플치과">
  <nav><!-- 메뉴(GNB)가 여기 들어감 --></nav>
  <a href="tel:000-0000-0000">전화상담</a>
</header>
```

### 내비게이션 / GNB (Navigation / Global Nav Bar)
- **무엇:** 사이트 전체를 돌아다니는 **주 메뉴**. "GNB = 전역 내비게이션 바".
- **어디:** 보통 헤더 안. (페이지 안에서만 쓰는 메뉴는 "LNB = 지역 내비").
- **샘플:**
```html
<nav>
  <a href="/treatments/implant">임플란트</a>
  <a href="/treatments/invisalign">투명교정</a>
  <a href="/doctors">의료진</a>
  <a href="/blog">블로그</a>
</nav>
```
- **GEO 연결:** 이 메뉴 구조가 `SiteNavigationElement` 스키마로 봇에게 "이 사이트의 핵심 페이지 목록"을 알려준다 (우수사례에서 실측됨).

### 푸터 (Footer)
- **무엇:** 페이지 맨 아래 띠. 주소·전화·사업자정보·약관·**키워드 링크**.
- **어디:** 모든 페이지 최하단 공통.
- **GEO 연결:** "지역+업종" 키워드 전용 페이지를 **푸터에 작은 링크로 배치** (01 문서 5.4). 사람 눈엔 덜 띄지만 봇은 읽는다.
- **샘플:**
```html
<footer>
  <p>샘플치과 | D시 E동 샘플로 123 | 000-0000-0000</p>
  <p>사업자등록번호 000-00-00000 | 대표 김철수 외 2명</p>
  <nav class="footer-keywords">
    <a href="/area/d-city">D시 치과</a>
    <a href="/area/e-dong">E동 치과</a>
  </nav>
</footer>
```

## 2. 첫 화면 영역

### 히어로 / 메인 비주얼 (Hero / Main Visual / Key Visual)
- **무엇:** 페이지를 열면 **가장 먼저 크게 보이는** 영역. 대표 이미지 + 핵심 한 문장 + 버튼.
- **어디:** 헤더 바로 아래, 첫 화면(스크롤 전).
- **샘플:**
```html
<section class="hero">
  <h1>D시 E동 치과, 365일 진료</h1>
  <p>전문의 다수, 임플란트·투명교정 전문</p>
  <a class="btn" href="/reservation">진료 예약</a>   <!-- 이게 CTA -->
</section>
```

### CTA (Call To Action, 행동 유도 버튼)
- **무엇:** 방문자가 **눌렀으면 하는 행동**을 유도하는 버튼. "예약하기", "전화상담", "상담신청".
- **어디:** 히어로·각 섹션 끝·푸터 등 곳곳.
- **샘플:** `<a class="btn-primary" href="/reservation">지금 예약하기</a>`

### 히어로 카피 / 헤드라인 (Headline)
- **무엇:** 히어로의 **큰 제목 한 줄**. 보통 `<h1>` 태그 = 페이지에서 가장 중요한 제목.
- **GEO 연결:** `<h1>`은 JSON-LD의 `headline`과 연결돼 "이 페이지의 주제"를 봇에게 알린다.

## 3. 본문 구성단위

### 섹션 (Section)
- **무엇:** 본문을 이루는 **주제별 덩어리**. 세로로 여러 개가 쌓인다 (서비스안내 → 전문가 → 후기 → FAQ).
- **샘플:**
```html
<section id="doctors">
  <h2>의료진 소개</h2>   <!-- 섹션 제목은 보통 h2 -->
  <div class="cards"><!-- 카드들 --></div>
</section>
```

### 카드 (Card)
- **무엇:** 정보를 **네모 박스 하나**에 담은 단위. 사진+제목+요약. 여러 개를 격자로 나열.
- **어디:** 전문가 목록, 블로그 글 목록, 서비스 항목 등.
- **샘플:**
```html
<div class="card">
  <img src="/doctor1.jpg" alt="김철수 대표원장">
  <h3>김철수 대표원장</h3>
  <p>○○대학교 치의학대학원 석사</p>
</div>
```

### 그리드 / 레이아웃 (Grid / Layout)
- **무엇:** 카드·섹션을 **몇 칸으로 배열**할지 정하는 격자 틀. "3단 그리드 = 한 줄에 3개".

### 콘텐츠 위계: H1 → H2 → H3
- **무엇:** 제목의 **계급**. H1(페이지 대표, 1개) → H2(섹션 제목) → H3(소제목).
- **GEO 연결:** 봇은 이 위계로 글 구조를 읽는다. **위계가 엉키면 봇이 내용 파악에 실패** (분석 핵심).

### FAQ (자주 묻는 질문)
- **무엇:** 질문-답변 묶음 섹션.
- **GEO 연결:** `FAQPage` 스키마로 만들면 **AI 답변에 그대로 인용**됨 (AEO 핵심). 우수사례는 글마다 Q&A 5쌍 운영.
- **샘플:**
```html
<section class="faq">
  <h2>자주 묻는 질문</h2>
  <details><summary>투명교정은 아프지 않나요?</summary><p>초기에 약간의...</p></details>
</section>
```

## 4. 보이지 않지만 중요한 부분 (`<head>` 안 = 봇이 읽는 영역)

> 화면엔 안 보이지만 HTML 맨 위 `<head>`에 들어가는, **검색엔진·AI봇용 정보**.

### 메타 태그 (Meta Tags)
- **무엇:** 페이지 **설명·제목** 등을 검색엔진에 알려주는 정보.
- **샘플:**
```html
<head>
  <title>D시 E동 치과 | 샘플치과</title>                        <!-- 검색결과 파란 제목 -->
  <meta name="description" content="365일 진료, 전문의 다수...">  <!-- 검색결과 회색 설명 -->
</head>
```

### OG 태그 / 오픈그래프 (Open Graph)
- **무엇:** 카톡·페북에 링크 공유 시 뜨는 **미리보기(썸네일+제목)** 정보.
- **샘플:** `<meta property="og:image" content="/og-image.jpg">`

### JSON-LD / 구조화 데이터 (Structured Data)
- **무엇:** 봇이 읽는 **사실 데이터 묶음** (상호·주소·좌표·작성자·FAQ). **GEO의 심장.**
- **어디:** `<head>` 안 `<script type="application/ld+json">`.
- **샘플:**
```html
<script type="application/ld+json">
{ "@context":"https://schema.org", "@type":"Dentist",
  "name":"샘플치과", "telephone":"000-0000-0000",
  "address":{ "@type":"PostalAddress", "addressLocality":"D시 ○○구" } }
</script>
```

### canonical (정규 URL)
- **무엇:** 같은 내용이 여러 주소로 보일 때 **"진짜 대표 주소는 이것"**이라고 지정. 중복 패널티 방지.
- **샘플:** `<link rel="canonical" href="https://sample-dental.example.com/blog/abc">`

### SSR / CSR (서버 렌더링 / 클라이언트 렌더링)
- **무엇:** 화면을 **누가 그리느냐**. SSR=서버가 완성해서 보냄, CSR=브라우저가 나중에 그림.
- **GEO 연결:** JSON-LD·메타는 **반드시 SSR로** `<head>`에 박혀 나와야 봇이 첫 응답에서 읽는다.

## 5. 사이트 전체 차원 파일 (페이지가 아닌, 사이트 루트의 파일)

| 용어 | 무엇 | 샘플 위치 |
|------|------|-----------|
| **robots.txt** | 크롤러에게 "어디는 봐도 되고 어디는 막는다" 안내 | `example.com/robots.txt` |
| **sitemap.xml** | 사이트의 **전체 페이지 목록** (봇용 지도) | `example.com/sitemap.xml` |
| **llms.txt** | AI(LLM)에게 사이트 핵심을 요약해 주는 신규 파일 | `example.com/llms.txt` |
| **favicon** | 브라우저 탭에 뜨는 작은 아이콘 | `/favicon.ico` |

## 6. 자주 헷갈리는 용어 짝

| 헷갈리는 짝 | 차이 |
|------------|------|
| **헤더 vs `<head>`** | 헤더 = 화면 위 띠(눈에 보임) / `<head>` = HTML 맨 위 봇용 정보(안 보임) |
| **푸터 키워드링크 vs 공유버튼** | 키워드링크 = GEO용 내부 링크(봇이 읽음) / 공유버튼 = 방문자가 SNS에 퍼가는 위젯(봇 신뢰신호 아님) |
| **GNB vs LNB** | GNB = 사이트 전역 메뉴 / LNB = 특정 페이지 안 보조 메뉴 |
| **랜딩페이지 vs 일반페이지** | 랜딩 = 특정 키워드/광고로 유입시키는 단일 목적 페이지 / 일반 = 상시 메뉴 페이지 |
| **메타 description vs 본문** | description = 검색결과에 뜨는 요약(봇용) / 본문 = 실제 읽는 글 |
| **author.sameAs vs 공유 아이콘** | sameAs = 작성자 본인의 신원 증명(JSON-LD, 봇용 E-E-A-T 신호) / 공유 아이콘 = 방문자용 위젯 |

## 한 줄 요약

> **화면에 보이는 부분(헤더·히어로·섹션·카드·푸터)** 과 **안 보이지만 봇이 읽는 부분(`<head>`의 메타·JSON-LD, 루트의 robots/sitemap/llms)** 으로 나뉜다. **GEO는 후자를 잘 채우는 일이다.**
